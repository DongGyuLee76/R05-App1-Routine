STEP 1

📦 배포를 위한 로컬 파일 준비

배포 시 원활한 의존성 설치 및 구동을 위해 로컬 작업 디렉토리에 필수 설정 파일들을 확인/수정해야 합니다. 이미 패치가 진행되었습니다.

1. requirements.txt 검사

로컬에 Render 배포용 패키지 명세서인 requirements.txt가 자동으로 작성되었습니다. gunicorn은 프로덕션급 웹 서버 구동을 위해 필수로 탑재되어 있습니다.

Flask>=2.2.0 Werkzeug>=2.2.0 gunicorn>=20.1.0

2. app_v1.py 동적 호스트/포트 바인딩 확인

서버 실행 포트를 고정하지 않고 클라우드가 제공하는 동적 환경변수(PORT) 및 외부 접근 허용 IP(0.0.0.0)에 유동적으로 바인딩되도록 app_v1.py 하단부가 정상 패치되었습니다.

if __name__ == '__main__': port = int(os.environ.get('PORT', 5100)) app.run(debug=True, host='0.0.0.0', port=port)
STEP 2

🐙 GitHub에 소스코드 푸시

Render.com은 GitHub 저장소를 원격으로 감지하여 커밋 푸시 시 자동으로 빌드하고 배포합니다. 로컬 소스 코드를 GitHub에 업로드하세요.

# 1. git 저장소 초기화 및 원격 연결 (아직 초기화되지 않은 경우) git init git remote add origin https://github.com/사용자아이디/레포지토리이름.git # 2. 변경사항 추가 및 커밋 git add . git commit -m "feat: login system & user isolated DB & render deploy configurations" # 3. 브랜치 확인 및 원격 저장소로 업로드 git branch -M main git push -u origin main

⚠️ 보안 및 용량 팁 (중요)

로컬의 임시 데이터베이스 파일(routine_main.db, users/routine_*.db) 및 기존 백업(*.db.backup)은 원격 레포지토리에 푸시되지 않도록 .gitignore에 명시해주는 것이 보안상 유리하며, 데이터는 배포 환경에서 동적 생성됩니다.

STEP 3

🚀 Render.com 웹 서비스 생성 및 연동

배포 대시보드에서 새로운 웹 서비스(Web Service)를 생성하고 GitHub 저장소를 가져와 아래의 중요 파라미터를 입력합니다.

설정 항목 (Field) 지정 값 (Value)
Service Type Web Service
Language Python
Build Command pip install -r requirements.txt
Start Command gunicorn app_v1:app

설정 방법 상세:

  1. Render.com 대시보드 로그인 후 우측 상단의 New + 버튼 클릭 후 Web Service를 선택합니다.
  2. 연동된 GitHub에서 방금 커밋을 보낸 레포지토리를 골라 Connect를 누릅니다.
  3. 서비스 이름(예: my-routine-tracker)을 정의하고, 파이썬 인스턴스 환경을 무료 티어인 Free 플랜으로 선택합니다.
  4. 위 표의 Build Command 및 Start Command를 명확히 기재해줍니다.
STEP 4

💾 SQLite 데이터 지속성 관리 정책 (필독)

Flask 웹앱이 SQLite 기반의 로컬 DB 파일(routine_main.db, users/routine_*.db)을 쓰고 있으므로, Render의 특징에 맞춰 데이터를 유지할 전략을 선택해야 합니다.

Render의 Persistent Disk 기능을 마운트하여 배포/재시작과 무관하게 데이터베이스를 영구 보존하는 표준적인 방법입니다. (월 $7 인스턴스 구동 필요)

  1. 배포 설정 완료 후 서비스 관리 콘솔 좌측 메뉴에서 Disks 탭으로 이동합니다.
  2. Add Disk 버튼을 누르고 아래 명세를 기입하여 생성합니다:
    • Name: routine-data-disk
    • Mount Path: /opt/render/project/src/data (이 마운트된 디렉토리에 DB 보관)
    • Size: 1 GB (루틴용으로는 충분함)
  3. 환경변수 / 코드 튜닝 팁: 디스크 마운트 경로를 데이터베이스 저장 경로로 활성화하기 위해, app_v1.py의 DB 경로 변수를 다음과 같이 마운트 디렉토리를 바라보도록 수정합니다:
    # 기존 경로 BASE_DIR = os.path.dirname(os.path.abspath(__file__)) # Render Persistent Disk 마운트 감지 및 마운트 경로 적용 if os.path.exists('/opt/render/project/src/data'): DB_DIR = '/opt/render/project/src/data' else: DB_DIR = BASE_DIR USERS_DIR = os.path.join(DB_DIR, 'users') MAIN_DB = os.path.join(DB_DIR, 'routine_main.db')

무료 인스턴스(Free Tier)를 그대로 유지하는 경우로, 15분 미사용 시 서버가 잠자기에 들어가며, 디스크 마운트를 지원하지 않아 재기동 시 데이터베이스 파일이 수시로 초기화(초기화 시 기본 admin 계정만 재생성)됩니다.

💡 무료 배포 환경을 위한 추천 대안

무료 플랜 배포 환경을 유지하면서 상용 데이터베이스 서비스를 무료로 쓰고 싶다면, Supabase 또는 Neon Tech 등의 외부 무료 PostgreSQL 클라우드 서비스를 활용하도록 코드를 SQLAlchemy 등으로 간단히 포팅하면 데이터를 완전히 영구 보존할 수 있습니다.

STEP 5

✨ 서비스 확인 및 완료

모든 빌드가 성공적으로 끝나면 대시보드 상단에 https://your-app-name.onrender.com 형식의 공개 웹 도메인 주소가 생성됩니다.

🎉 축하합니다! 배포가 최종 완료되었습니다.
